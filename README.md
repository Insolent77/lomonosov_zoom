# Мой Ломоносов — Zoom Webhook Demo

Тестовый Python-сайт для маршрутизации облачных записей Zoom по учебным чатам. **Это независимая демонстрация, не подключенная к реальному Ломоносову.**

## Локально

Python 3.10+; сторонние пакеты не требуются.

```powershell
$env:DEMO_MODE = "1"
python app.py
```

Открой http://127.0.0.1:8000 . Две группы используют одинаковый Meeting ID и разные Session UUID. Кнопки добавляют фиктивные ссылки в правильную группу.

## Render

Репозиторий содержит `render.yaml`. Разверни как Blueprint или Web Service из GitHub. В Render добавь **секретную** переменную окружения `ZOOM_WEBHOOK_SECRET_TOKEN` (получить в Zoom Marketplace, вкладка Feature); не публикуй её в репозитории и не присылай в переписке. `DEMO_MODE=0` для внешнего сервера. Публичный адрес будет вида `https://<service>.onrender.com`.

В Zoom Webhook Only App → Feature → Event Subscriptions добавь URL `https://<service>.onrender.com/webhooks/zoom`, нажми Validate, затем подпишись на `Recording Completed` (`recording.completed`). Обязательно убедись, что Zoom Cloud Recording включён. При утечке токена — Regenerate и обновление в Render.

## Маршрутизация

- `POST /webhooks/zoom` проверяет URL-validation challenge; для обычных событий проверяет timestamp и подпись `x-zm-signature`.
- `recording.completed`: сопоставляет `payload.object.uuid` и `payload.object.id` с уроком; сохраняет `share_url` только для однозначного совпадения; повторный UUID не дублирует сообщение.
- Тестовые UUID `test-uuid-math-101` и `test-uuid-physics-102` **не соответствуют реальным занятиям**. Чтобы получить сообщение от настоящего Zoom, нужно заранее внести реальные UUID и Meeting ID в таблицу lessons. Пока интерфейса назначения урока нет.
- `GET /health` служит для проверки работоспособности.

## Ограничения прототипа

* Демонстрационные учебные чаты — локальные записи SQLite, не Telegram и не чаты Django.
* На бесплатном Render диск временный; сообщения могут пропасть после перезапуска. Для реального тестирования желательно подключить постоянную БД.
* Отображение сайта не защищено авторизацией. **Не добавляй реальные ссылки Zoom или данные учеников, пока не будет авторизации и закрытого доступа.**
* Для настоящей интеграции нужно подключить модели занятий/чатов Django и способ однозначно сопоставлять Zoom-сеансы урокам.


## Входящие записи без привязки

Открой `/recordings`. Все успешно проверенные события `recording.completed` сохраняются в SQLite и отображаются независимо от сопоставления с учебной группой. Данные на бесплатном Render временные. Раздел **публичный**: реальные ссылки на записи нельзя считать приватными; для использования с учениками необходимо ограничение доступа.


## Импорт истории через Zoom API

В Render Environment добавь `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`, а также `ZOOM_USER_EMAIL` — почту пользователя Zoom, записи которого загружаются (для Server-to-Server OAuth `me` использовать нельзя). Аккаунт/пользователь должен быть доступен приложению и иметь включённую облачную запись. Открой `/recordings`, выбери дату и нажми «Загрузить из Zoom». API запрашивает `/users/{userId}/recordings` с гранулярным scope `cloud_recording:read:list_user_recordings:admin`. Ссылки и страница ПУБЛИЧНЫ, используйте только с согласия участников и учитывайте требования конфиденциальности. Для хранения записей нужна постоянная БД вместо временной SQLite на бесплатном Render.
